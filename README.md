## What is ZetaTron?

Less a chatbot. More a co-worker who never sleeps.

ZetaTron is a **self-directed AI agent**. It sets its own goals, works across your machine to reach them, and keeps going while you're away. You install it, you grant it permissions, and it starts working — no prompt required.

**Autonomy is the entire point of the software.** The permissions you hand it are the real decision here. Understand what you're giving it access to before you run it.

---

## What it can do (seven things it does without asking)

1. **Acts autonomously** — Sets goals, schedules its own work, and reacts to events with no prompt from you.
2. **Controls the machine** — Reads, writes, organizes, and executes files across the system you install it on.
3. **Communicates** — Sends messages and email, and manages the inboxes and channels you connect.
4. **Runs across machines** — Delegates work to other instances, shares one workspace, and coordinates the result.
5. **Remembers everything** — Permanent memory across sessions. Closing the app doesn't reset what it knows.
6. **Sharpens with use** — Agents get better with every run, adapting to the way you actually work.
7. **Creates its own tools** — Writes code, builds documents, and forges whatever tooling the job requires.

## Requirements

- **RAM:** Recommended
- **Model host:** A local model host (such as **LM Studio**) — **or** an API host with a key.

> **Model hosting note:** ZetaTron can self-host models inside the program for fully offline use, but self-hosting is very new and **extremely experimental**. For the best and most reliable results, use a third-party model host (LM Studio or a local API endpoint) as your default. Treat self-hosting as a bleeding-edge option for now.

### How consent is captured (clickwrap, not just a file)

This isn't a license sitting in the archive — it's **clickwrap**. The record of
acceptance is what makes it enforceable. Two enforcement layers:

1. **Windows installer (NSIS):** the installer shows a native license-acceptance
   page (this exact `EULA.txt`). It will not proceed past it without an explicit
   accept.
2. **In-app gate, every platform:** on first launch the app blocks on an
   acceptance overlay before anything else runs. The **I Agree** button stays
   disabled until you scroll the agreement to the end, so there's proof the
   terms were actually shown to you. Declining quits the app — there is no
   "use it anyway" path.

- **Windows users agree twice** — that's intentional. The first acceptance
  governs installation; the second (in-app) governs continued use.
- **What gets recorded:** on accept, the app writes an acceptance record
  (`eula-accepted.json`) with the version, acceptance timestamp, app version,
  and platform. `EULA_VERSION` is a single constant — bump it when terms change
  and every existing install re-prompts on next launch. Old consent never
  carries forward to new terms.
- **Fails closed:** if the acceptance check itself fails, the gate **blocks**
  rather than assuming consent. A corrupted or tampered record is treated as
  "not accepted."
